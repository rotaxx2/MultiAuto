# MultiAuto: продуктовые требования

## Назначение продукта

MultiAuto - коммерческая multi-tenant платформа для автомоек. Клиенты записываются через Telegram Bot и Telegram Mini App. Администраторы и владельцы управляют операционной частью через отдельную защищенную административную панель.

Платформа проектируется так, чтобы после MVP подключать несколько организаций и несколько филиалов внутри одной организации.

## Роли

В системе есть только три роли:

- `CLIENT` - клиент автомойки.
- `ADMIN` - администратор конкретной организации.
- `OWNER` - владелец конкретной организации.

Роли `WORKER`, `EMPLOYEE`, `STAFF` не используются. Операционные статусы записей меняет `ADMIN` или `OWNER`.

## Основные пользовательские сценарии клиента

1. Клиент открывает Telegram-бота.
2. Отправляет `/start`.
3. Backend получает Telegram user information.
4. Backend создает или находит клиента по Telegram User ID.
5. Клиент открывает Telegram Mini App.
6. Mini App работает с backend API.
7. Клиент добавляет автомобиль.
8. Клиент выбирает филиал, автомобиль, услугу, дату и слот.
9. Backend проверяет доступность и создает запись.
10. Клиент управляет текущими и прошлыми записями.
11. Клиент получает Telegram-уведомления.
12. После завершенной услуги клиент может оставить отзыв.

## Клиентские возможности MVP

- просмотр главной страницы Mini App;
- добавление, редактирование и удаление автомобиля;
- просмотр услуг, цен и длительности;
- выбор автомобиля;
- выбор услуги;
- выбор даты;
- просмотр доступных слотов;
- создание записи;
- просмотр текущей записи;
- перенос записи;
- отмена записи;
- просмотр истории записей;
- просмотр статуса записи;
- получение Telegram-уведомлений;
- создание отзыва после завершенной записи.

## Административные возможности MVP

Для `ADMIN`:

- dashboard организации;
- управление записями;
- календарь записей;
- управление клиентами организации;
- управление автомобилями клиентов организации;
- управление услугами;
- управление боксами;
- управление расписанием;
- управление статусами записей;
- просмотр отзывов;
- просмотр статистики своей организации.

Для `OWNER` дополнительно:

- управление администраторами;
- управление филиалами;
- настройки организации;
- общая аналитика организации.

## Multi-tenant модель

Основная структура:

```text
Organization
  -> Branch
  -> Services
  -> Workstations
  -> Working Schedule
  -> Administrators
  -> Customers
  -> Cars
  -> Bookings
```

Каждая бизнес-сущность, относящаяся к автомойке, должна иметь `organization_id`. Сущности, привязанные к филиалу, дополнительно имеют `branch_id`.

## Вне рамок MVP

На текущем этапе не реализуются:

- онлайн-оплата;
- промокоды;
- маркетинговые рассылки;
- подписки для автомоек;
- программа лояльности;
- бонусные баллы;
- VIP-уровни;
- учетные записи обычных сотрудников или мойщиков.

Архитектура должна позволять добавить эти модули позже, но текущая документация не должна вводить их как обязательную часть MVP.

## Критерии готовности архитектурного этапа

- описана domain model;
- описаны роли и permissions;
- описана tenant isolation;
- описана логика бронирования без double booking;
- описан предварительный API;
- описаны Telegram Bot и Mini App flows;
- описаны admin flows;
- описаны меры безопасности;
- сформирован roadmap разработки.
