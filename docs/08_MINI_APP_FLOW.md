# Mini App flow

## Назначение Mini App

Telegram Mini App является клиентским интерфейсом для записи на автомойку. Все критичные проверки выполняет backend.

## Первый запуск

1. Клиент открывает Mini App из Telegram Bot.
2. Mini App получает Telegram `initData`.
3. Mini App отправляет `initData` в backend.
4. Backend проверяет Telegram auth и возвращает session token.
5. Mini App загружает главную страницу.

## Главная страница

На главной странице клиент видит:

- ближайшую активную запись, если она есть;
- быстрый переход к созданию записи;
- список своих автомобилей;
- переход к истории записей;
- статус уведомлений через Telegram.

## Автомобили

Поля автомобиля:

- `brand`;
- `model`;
- `license_plate`;
- `color`;
- `vehicle_type`.

Сценарии:

- добавить автомобиль;
- редактировать автомобиль;
- удалить автомобиль;
- выбрать автомобиль для записи.

Mini App должен показывать только автомобили текущего клиента.

## Создание записи

Сценарий:

1. Клиент выбирает филиал.
2. Клиент выбирает автомобиль.
3. Клиент выбирает услугу.
4. Mini App показывает длительность и цену.
5. Клиент выбирает дату.
6. Mini App запрашивает доступные слоты.
7. Backend возвращает только реально доступные слоты.
8. Клиент выбирает слот.
9. Mini App отправляет запрос на создание записи.
10. Backend повторно проверяет доступность и создает запись.
11. Mini App показывает подтверждение.

Если слот стал недоступен между просмотром и созданием, backend возвращает `SLOT_UNAVAILABLE`, а Mini App обновляет список слотов.

## Текущая запись

Клиент видит:

- услугу;
- автомобиль;
- филиал;
- дату и время;
- статус;
- цену;
- доступные действия.

Действия:

- перенести запись, если статус позволяет;
- отменить запись, если статус позволяет.

## История

История включает завершенные, отмененные и пропущенные записи:

- `COMPLETED`;
- `CANCELLED`;
- `NO_SHOW`.

Для `COMPLETED` записи клиент может оставить отзыв, если отзыв еще не создан.

## Статусы записи для клиента

Клиент видит человекочитаемые названия для:

- `PENDING`;
- `CONFIRMED`;
- `ARRIVED`;
- `IN_PROGRESS`;
- `READY`;
- `COMPLETED`;
- `CANCELLED`;
- `NO_SHOW`.

Mini App не должен позволять клиенту вручную менять статус записи, кроме действий отмены или переноса через отдельные endpoint'ы.

## Ошибки и пустые состояния

Mini App должен обрабатывать:

- нет автомобилей;
- нет активных услуг;
- нет доступных слотов;
- слот стал недоступен;
- запись уже отменена;
- запись нельзя перенести из текущего статуса;
- ошибка Telegram authentication.

## Что Mini App не делает

- не хранит роль как источник истины;
- не обращается к Admin API;
- не показывает чужие записи;
- не принимает административные решения;
- не обходит backend validation.
