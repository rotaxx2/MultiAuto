# Mini App flow

## Назначение Mini App

Telegram Mini App является клиентским интерфейсом для записи на автомойку. Все критичные проверки выполняет backend.

Текущая реализация Mini App:

- React + TypeScript + Vite;
- API layer в `frontend/src/api`;
- Telegram WebApp helpers в `frontend/src/utils/telegram.ts`;
- страницы `Home`, `Profile`, `Cars`, `Bookings`;
- страницы `Services` и `Branches`;
- нижняя навигация для мобильного экрана Telegram;
- использование Telegram theme variables;
- базовые состояния loading, error, empty и unauthorized.

## Первый запуск

1. Клиент открывает Mini App из Telegram Bot.
2. Mini App получает Telegram `initData`.
3. Mini App отправляет `initData` в backend.
4. Backend проверяет Telegram auth и возвращает session token.
5. Mini App загружает главную страницу.

Frontend отправляет на backend только `initData` и `start_param`. Он не отправляет произвольный `telegram_id` как источник истины.

## Главная страница

На главной странице клиент видит:

- ближайшую активную запись, если она есть;
- быстрый переход к созданию записи;
- список своих автомобилей;
- переход к истории записей;
- статус уведомлений через Telegram.

## Автомобили

Поля автомобиля:

- `brand`;
- `model`;
- `license_plate`;
- `color`;
- `vehicle_type`.

Сценарии:

- добавить автомобиль;
- редактировать автомобиль;
- удалить автомобиль;
- выбрать автомобиль для записи.

Mini App должен показывать только автомобили текущего клиента.

Текущая реализация поддерживает:

- список автомобилей;
- добавление автомобиля;
- редактирование автомобиля;
- удаление автомобиля.

Все операции идут через `/api/my-cars/`; frontend не передает `user_id`.

## Услуги и филиалы

Mini App показывает:

- активные услуги организации клиента;
- активные филиалы организации клиента.

Услуги на текущем этапе принадлежат организации целиком. Endpoint `/api/branches/{id}/services/` проверяет принадлежность филиала организации клиента и возвращает активный каталог услуг этой организации.

## Создание записи

Сценарий:

1. Клиент выбирает филиал.
2. Клиент выбирает услугу.
3. Клиент выбирает автомобиль.
4. Клиент выбирает дату.
5. Mini App запрашивает `/api/branches/{branch_id}/availability/?date=YYYY-MM-DD&service_id={id}`.
6. Backend возвращает только реально доступные слоты без данных о workstation и чужих клиентах.
7. Клиент выбирает слот.
8. Mini App показывает подтверждение: филиал, услуга, длительность, автомобиль, дата, время и цена из backend.
9. Mini App отправляет `POST /api/bookings/`.
10. Backend повторно проверяет доступность, назначает свободный workstation, рассчитывает `end_at`, сохраняет snapshot цены и создает `Booking`.
11. Mini App переводит клиента на экран `Мои записи`.

Frontend не передает `organization_id`, `client_id`, `workstation_id`, `end_at`, `status` или `price`.

Если слот стал недоступен между просмотром и созданием, backend возвращает validation error, а Mini App показывает ошибку и позволяет обновить список слотов.

## Текущая запись

Клиент видит:

- услугу;
- автомобиль;
- филиал;
- дату и время;
- статус;
- цену;
- доступные действия.

Действия:

- перенести запись, если статус позволяет;
- отменить запись, если статус позволяет.

## История

История включает завершенные, отмененные и пропущенные записи:

- `COMPLETED`;
- `CANCELLED`;
- `NO_SHOW`.

Для `COMPLETED` записи клиент может оставить отзыв, если отзыв еще не создан.

## Статусы записи для клиента

Клиент видит человекочитаемые названия для:

- `PENDING`;
- `CONFIRMED`;
- `ARRIVED`;
- `IN_PROGRESS`;
- `READY`;
- `COMPLETED`;
- `CANCELLED`;
- `NO_SHOW`.

Mini App не должен позволять клиенту вручную менять статус записи, кроме действий отмены или переноса через отдельные endpoint'ы.

## Ошибки и пустые состояния

Mini App должен обрабатывать:

- нет автомобилей;
- нет активных услуг;
- нет доступных слотов;
- слот стал недоступен;
- запись уже отменена;
- запись нельзя перенести из текущего статуса;
- ошибка Telegram authentication.

Если приложение открыто вне Telegram и нет сохраненного server-side token, Mini App показывает unauthorized state с просьбой открыть приложение через Telegram-бота.

## Что Mini App не делает

- не хранит роль как источник истины;
- не обращается к Admin API;
- не показывает чужие записи;
- не принимает административные решения;
- не обходит backend validation.

## Environment

Frontend использует:

```text
VITE_API_URL
```

Это публичный адрес backend API. Секреты Telegram Bot в frontend environment не передаются.
