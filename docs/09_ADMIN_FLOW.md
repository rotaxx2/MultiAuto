# Admin flow

## Назначение Admin App

Admin App - отдельная защищенная административная часть для `ADMIN` и `OWNER`.

Клиентский Telegram Mini App и Admin App должны быть разделены по маршрутам, auth flow и API namespace.

## Вход администратора

1. `ADMIN` или `OWNER` открывает Admin App.
2. Вводит административные учетные данные.
3. Backend проверяет credentials.
4. Backend проверяет, что аккаунт активен.
5. Backend возвращает admin session token.
6. Admin App запрашивает `/api/v1/admin/auth/me`.
7. UI строится на основе роли, но backend все равно проверяет права на каждом endpoint.

## Dashboard

Доступ: `ADMIN`, `OWNER`.

Показывает:

- записи на сегодня;
- ближайшие записи;
- количество записей по статусам;
- загрузку боксов;
- базовую выручку по завершенным записям;
- последние отзывы.

Все данные фильтруются по `organization_id`.

## Bookings

Доступ: `ADMIN`, `OWNER`.

Возможности:

- список записей;
- фильтры по дате, филиалу, статусу, услуге;
- просмотр деталей записи;
- изменение статуса по допустимому workflow;
- комментарий администратора.

На Stage 6 реализованы endpoints:

- `GET /api/admin/bookings/`;
- `GET /api/admin/bookings/{id}/`;
- `PATCH /api/admin/bookings/{id}/`.

`PATCH` принимает только `status` и `admin_comment`. Администратор не может через обычный PATCH менять `organization`, `client`, `car`, `service`, `workstation`, `start_at` или `end_at`. Создание от имени клиента, перенос и календарные drag-and-drop операции остаются отдельными будущими задачами.

## Calendar

Доступ: `ADMIN`, `OWNER`.

Календарь должен показывать записи по:

- дню;
- неделе;
- филиалу;
- боксу;
- статусу.

Календарь не должен позволять создавать пересекающиеся записи. Любые drag-and-drop переносы должны идти через backend Booking Engine.

## Customers

Доступ: `ADMIN`, `OWNER`.

Возможности:

- список клиентов организации;
- поиск по имени, телефону, Telegram username;
- просмотр карточки клиента;
- просмотр автомобилей клиента;
- просмотр истории записей клиента;
- ручное создание клиента, если запись оформляется не через Telegram.

Ручной клиент может не иметь `telegram_user_id`, но тогда Telegram-уведомления невозможны до связывания с Telegram.

## Cars

Доступ: `ADMIN`, `OWNER`.

Возможности:

- просмотр автомобилей клиентов организации;
- создание автомобиля клиенту;
- редактирование автомобиля;
- удаление автомобиля через soft delete.

## Services

Доступ: `ADMIN`, `OWNER`.

Поля услуги:

- название;
- описание;
- длительность;
- активность;
- базовая цена.

Услугу лучше деактивировать, а не физически удалять, если по ней уже есть записи.

## Workstations

Доступ: `ADMIN`, `OWNER`.

Возможности:

- список боксов филиала;
- добавление бокса;
- переименование бокса;
- включение и выключение активности.

Неактивный бокс не участвует в расчете новых слотов, но исторические записи сохраняются.

## Schedule

Доступ: `ADMIN`, `OWNER`.

Возможности:

- настройка рабочих дней;
- настройка времени открытия и закрытия;
- настройка перерывов;
- настройка исключений на конкретную дату;
- просмотр результата по филиалу.

Изменение расписания не должно автоматически переносить существующие записи. Если изменение создает конфликт, система должна показать предупреждение.

## Reviews

Доступ: `ADMIN`, `OWNER`.

Возможности:

- список отзывов;
- фильтрация по рейтингу;
- переход к записи;
- переход к клиенту.

## Settings

Доступ:

- `ADMIN` - базовые настройки, разрешенные владельцем;
- `OWNER` - полные настройки организации.

## Owner-only разделы

### Administrators

`OWNER` может:

- создавать `ADMIN`;
- деактивировать `ADMIN`;
- менять имя и email администратора;
- сбрасывать пароль администратора.

`OWNER` не должен понижать себя так, чтобы в организации не осталось владельца.

### Branches

`OWNER` может:

- создавать филиалы;
- редактировать филиалы;
- активировать и деактивировать филиалы;
- смотреть статистику по филиалам.

### Organization Settings

`OWNER` управляет:

- названием организации;
- timezone по умолчанию;
- валютой;
- настройками подтверждения записи;
- базовыми настройками уведомлений.

### Analytics

`OWNER` видит:

- общую статистику организации;
- сравнение филиалов;
- динамику записей;
- загрузку боксов;
- выручку по завершенным записям.

## Audit

Административные действия должны попадать в audit log:

- создание и изменение услуг;
- изменение расписания;
- изменение статуса записи;
- перенос и отмена записи;
- управление администраторами;
- изменение настроек организации.
